# Southern Breeze HVAC Repairs — Emergency AC Repair Landing Page

Single-page, mobile-first site built to out-convert an Angi / BBB / YellowPages / Facebook listing:
one job, one page, one tap to a ringing phone.

**Primary phone:** (228) 255-9190 · **Service area:** Diamondhead, Kiln, Bay St. Louis & Hancock County, MS · **Hours:** 24/7

Stack: **Next.js 14 (App Router) + Tailwind CSS**, zero images, zero webfonts, deployable to Vercel as-is.

---

## The conversion path (in order of priority)

| Priority | Element | Where |
| --- | --- | --- |
| 1 | **Sticky bottom call bar** — always on screen, `tel:` link, survives every scroll position | `app/components/StickyCallBar.jsx` |
| 2 | **Hero tap-to-call button** — full width, above the fold with no scrolling | `app/page.jsx` → `Hero` |
| 3 | Phone number as a tappable `tel:` link everywhere it appears (hero, header, services band, service area, request section, form validation errors, FAQ answer, final CTA, footer) | all sections |
| 4 | **Request-service form** (name, phone, service, urgency) for people who won't call yet | `app/components/RequestForm.jsx` |
| 5 | Trust bar directly under the hero: licensed/insured · 24/7 + ~45-min avg response · 4.6★ / 38 reviews · 14 yrs local | `TrustBar` |

Above-the-fold contents (checked against a 375×667 viewport): brand name, value prop, live "answering now"
badge, tappable phone number, and the primary CTA — a visitor can call without scrolling.

## Local SEO

  - Title: `Emergency AC Repair, Diamondhead MS | Southern Breeze HVAC` (59 chars)
  - Description: 24/7 emergency AC repair + cities + licensed/insured + 14 yrs + ~45-min response + phone
- **Structured data** (`app/page.jsx`, `@graph`):
  - `HVACBusiness` — name, `tel:+12282559190`, address (locality/ZIP only — no street address was supplied),
    `areaServed` (cities + Hancock County), 24/7 `openingHoursSpecification`, `aggregateRating` (4.6 / 38),
    both reviews, `makesOffer` per service, `priceRange`, plus `additionalProperty` for years in business
    and average response time.
  - `FAQPage` — mirrors the visible FAQ section.
- `robots.txt` + `sitemap.xml` generated by `app/robots.js` / `app/sitemap.js`.
- ZIP codes surface in the service-area section for "near me" relevance.

## Speed

- No photographic assets, no carousel, no autoplay video, no icon library — every icon is inline SVG on
  `currentColor` (`app/components/icons.jsx`).
- System font stack only: no webfont request, no FOIT/FOUT.
- One CSS file, one small client component (the form); everything else is a server component.
- FAQ uses native `<details>` — zero JS for the accordion.
- `prefers-reduced-motion` respected for the hero pulse and smooth scrolling.

## Deploy

```bash
npm install
npm run dev      # http://localhost:3000
npm run build && npm start
```

**Vercel:** import the repo at `github.com/CHATSCD/southern-breeze-hvac` → framework auto-detects Next.js →
add the env vars below → deploy. No build settings or overrides needed.
(This project's Vercel deploy hook is not wired up on the agent side, so the import step is manual — it takes
about a minute.)

### Environment variables

| Key | Required | Notes |
| --- | --- | --- |
| `SUPABASE_URL` | recommended | Supabase project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | recommended | server-side only; bypasses RLS for lead inserts |
| `NEXT_PUBLIC_SITE_URL` | recommended | real domain, used for canonical URL, sitemap, JSON-LD |

If the Supabase keys are missing, `POST /api/request-service` returns `{ ok: false, error: "not_configured" }`,
logs the lead server-side, and shows the visitor **"calling is faster"** with the phone number — a lead is never
silently swallowed.

### Where form leads go

Table **`public.service_requests`** in Supabase. Note: this table already existed and was shared, so the build
worked with the existing shape rather than recreating it.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | bigint | sequence default |
| `created_at` | timestamptz | default `now()` |
| `name` | text | required by the API route |
| `phone` | text | required by the API route (10+ digits) |
| `service` | text | from the service dropdown |
| `urgency` | text | `emergency` / `today` / `soon` |
| `city` | text | **added by this build** (was missing) |
| `notes` | text | |
| `source` | text | this form writes `landing-page` |
| `user_agent` | text | |

Verified end to end: a row matching the exact API payload inserts cleanly.

RLS is enabled. Five duplicate permissive anon-`INSERT` policies existed on the table; four were dropped so a
single `allow anon insert service requests` policy remains (permissive policies OR together, so any existing
anon-key client is unaffected). This site posts with the service-role key from the server, so it doesn't depend
on that policy either way.

To get notified instantly, add a Supabase **Database Webhook** on `service_requests` INSERT → email/SMS/Twilio,
or point a Zapier/Make hook at the same table. A saved lead nobody sees is a lost job.

## Things to confirm / change before it goes live

1. **`NEXT_PUBLIC_SITE_URL`** currently falls back to the placeholder `https://southern-breeze-hvac.vercel.app`.
   Set the real domain in Vercel; it feeds the canonical tag, sitemap and JSON-LD.
2. **ZIP codes** — Diamondhead 39525, Kiln 39556, Bay St. Louis 39520 appear in the service-area section.
   Confirm them for the exact footprint. Waveland (39576) is also in Hancock County and is a one-line add to
   `SITE.cities` in `lib/site.js` if it's served.
3. **`priceRange: "$$"`** in the JSON-LD is a placeholder. Replace with the real directory-style range, or delete
   the field.
4. **Diagnostic fee wording** — the FAQ says a diagnostic charge applies and is quoted up front. If the diagnostic
   is free or a fixed dollar amount, update `FAQS` in `lib/site.js`.
5. **Address** — JSON-LD intentionally contains only city/state/ZIP (no street address was provided). Add
   `streetAddress` and `geo` coordinates once confirmed; a verified Google Business Profile with matching NAP is
   the single highest-leverage local SEO move available here.
6. **No fabricated details:** no license number, no street address, no third testimonial, and no photo assets were
   invented. Only the supplied business facts appear on the page.

## Editing content

`lib/site.js` holds phone, hours, years, rating, cities, services, testimonials and FAQs. `app/page.jsx` renders
sections in this order: Hero → Trust bar → Services → Service area → Reviews → Request service → FAQ → Final CTA
→ Footer. Anchors: `#services`, `#area`, `#reviews`, `#request`, `#faq`.
